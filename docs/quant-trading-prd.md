# 量化交易全流程迭代方案 — PRD

> **项目定位：** 将 `autoresearch` 的自主实验能力 + `ai-hedge-fund` 的多智能体投资决策框架，打造一套**可持续自我迭代的 AI 量化交易系统**。

---

## 1. 背景与目标

### 1.1 现状

| 组件 | 说明 |
|---|---|
| `liuxing95/autoresearch` | 基于自主 AI agent 的实验迭代框架，每轮实验 5 分钟，通过 `val_bpb` 度量自动记录保留/丢弃决策 |
| `virattt/ai-hedge-fund` | 多智能体对冲基金模拟，包含基本面、技术面、情感面多路分析 agent 以及回测引擎 |

### 1.2 核心目标

1. **回测 → 实盘的完整闭环**：从历史数据回测 → 策略评估 → 论文/代码自动优化 → 纸面交易 → 实盘。
2. **自主迭代**：借鉴 autoresearch "改代码 → 训练 → 对比 → 保留/丢弃" 范式，把同样的自主实验循环搬到量化策略研究上。
3. **可解释性**：每轮迭代均有结构化日志，策略改动可追溯、可回滚。

## 2. 用户故事

### Epic 1 — 策略研究

- **US-01** 作为量化研究员，我希望 AI agent 自动生成并回测候选策略，无需我手动编写每个策略。
- **US-02** 作为量化研究员，我希望系统自动对比多个策略的夏普比、最大回撤、年化收益，并保留最优版本。
- **US-03** 作为量化研究员，我希望当策略表现劣化时，系统自动回滚到上一个最优 commit。

### Epic 2 — AI Agent 投资决策

- **US-04** 作为用户，我希望 ai-hedge-fund 的多路 agent（Buffett、情感、技术面等）能读取我自己的 K 线数据和基本面数据，而非仅限于美股。
- **US-05** 作为用户，我希望系统支持 A 股 / 港股 / 美股 数据源的接入。

### Epic 3 — 回测与实盘对接

- **US-06** 作为用户，我希望通过统一接口切换"回测模式"和"纸面交易模式"，代码改动最小化。
- **US-07** 作为用户，我希望有风险控制层在每次下单前校验仓位、最大亏损阈值。

### Epic 4 — 监控与报告

- **US-08** 作为用户，我希望每日自动生成实验报告，包含：策略变更记录、关键指标趋势图、当前持仓快照。

## 3. 功能需求

### 3.1 必须有（MVP）

|---|---|---|
| F-01 | 数据层：统一行情数据接口，支持 yfinance / Tushare / AKShare | P0 |

## 4. 非功能需求

| 类别 | 要求 |
|---|---|
| 延迟 | 回测单只股票 1 年数据 < 5 秒 |
| 可复现 | 所有实验 seed 固定，结果可复现 |
| 可观测 | 所有 agent 调用均写 structured log（JSON Lines） |
| 安全 | API Keys 通过 `.env` + `python-dotenv` 管理，不提交 git |
| 扩展性 | 新增 agent 只需实现统一 `BaseAgent` 接口 |

## 6. 里程碑

```
Week 1-2:   环境搭建 + 数据层 + 回测引擎集成 (F-01, F-02)
Week 3-4:   策略迭代循环 + 结果记录 (F-03, F-04)
Week 5-6:   风控模块 + 多路 agent 投票 (F-05, F-06)
Week 7-8:   纸面交易对接 + Dashboard (F-07, F-08)
Month 3+:   LLM 微调 / 多策略组合 / 实盘 (F-10, F-11, F-12)
```

---

## 7. 依赖与风险

| 风险 | 缓解措施 |
|---|---|
| LLM API 费用过高 | 设置每日 token 上限；优先用本地小模型（ollama / llama.cpp）做策略生成 |
| 历史数据质量差（A股） | 使用 Tushare Pro 专业数据源，加数据清洗管道 |
| 过拟合回测 | 分 in-sample / out-of-sample 数据集；启用 Walk-Forward 优化 |
| 实盘资金风险 | 强制先完成 ≥ 3 个月纸面交易验证再考虑实盘 |
